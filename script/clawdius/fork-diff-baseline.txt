# Clawdius fork-diff ratchet baseline
#
# The fork surface measured against the pinned upstream tag by script/clawdius/diff-stat.
# This baseline is the agreed size of the intentional fork diff: the fork MUST NOT grow beyond it
# without a recorded, reviewed disposition, keeping the diff small, isolated, and auditable.
# Update this file deliberately - for example after an upstream merge - by re-running:
#   script/clawdius/diff-stat
# and recording the new numbers below. The ratchet (script/clawdius/diff-stat --check, run in CI)
# fails when files-changed or insertions exceed these numbers.
#
# The large deletion count is dominated by removing a prebuilt vendor chat extension (a checked-in
# dist bundle); insertions and files-changed are the growth-relevant metrics for the ratchet.
#
# upstream_commit pins the base by SHA so the ratchet resolves even on a shallow CI checkout that
# has no upstream remote and cannot see the tag name; CI fetches this SHA before running --check.

# Disposition 2026-07-13 (+3 files, +1021 insertions): macOS login-Keychain credential resolution.
# The Claude Code CLI stores its OAuth credentials in the macOS login Keychain, not in the plaintext
# ~/.claude/.credentials.json (that file is only the fallback when the Keychain write fails, and the
# only store at all on Windows/Linux). Reading the file alone reported every signed-in mac user as
# "Signed out". The growth is three new files - the node credential resolver plus its two test suites -
# and the wiring to route the renderer's signed-in probe to the host that owns ~/.claude. Isolated to
# the clawdius-owned surface (platform/clawdius, contrib/clawdius, the clawdius-chat extension); no
# upstream file grows beyond the call-site edits needed to pass the probe through.

# Disposition 2026-07-16 (+0 files, +111 insertions): clamp a failed mission's error to one line and gate the
# Missions view on a real boot. A workflow failure arrives as a multi-line stack trace; rendered whole into a
# `flex-wrap: wrap` row it wrapped to eight lines, so three failures filled the sidebar and pushed the missions
# below them off screen. The row now paints the error's first line with the full text on its tooltip - what is
# painted shortens, what is known does not. The unit suite could not have caught this: it asserted the `data-*`
# hooks, which were correct throughout; only a real boot against a real config root showed it. So the e2e harness
# gains a missions scenario that opens the view and asserts rows are named workflow runs carrying a real status,
# which is now a standing gate. Growth is the clamp helper plus its two tests, the CSS rule, and that scenario;
# no new files, no upstream file touched.

# Disposition 2026-07-16 (+0 files, +115 insertions): report a torn record as a known gap. The transcript parser
# dropped an unparseable line and recorded nothing, so a read that LOST a record still reported `complete` - the
# one claim the completeness ladder exists to prevent. Probed against the compiled seam, a torn line returned
# {records:1, sawForeign:false} -> `complete`, while a merely-unmodeled record type returned `partial`: the label
# was backwards, degrading on readable content and staying silent on real loss. The parser now sets a `sawTorn`
# flag where it drops the line, and the four ladders share one `hasKnownGap` rule (torn OR unmodeled shape OR a
# windowed tail) instead of repeating it. `sawForeign` keeps degrading to `partial` - an unmodeled record is real
# content the view cannot surface, which is a genuine gap. The live tail is unaffected: an unterminated final line
# is skipped before any parse, so an actively-appended transcript stays `complete`. Growth is the flag, the shared
# rule, and two tests pinning torn-vs-live-tail. No new files; isolated to the clawdius-owned reader seam.

# Disposition 2026-07-16 (-4 files, -653 insertions): delete the unreachable mission control path, and CORRECT the
# three blocks above. Missions ships read-only; launching workflows from Clawdius is a roadmap item. A control
# cannot act on a mission Clawdius does not hold: it has a live SDK Query only for a session it launched itself, so
# a CLI-launched run - which is every mission on disk - has no handle to stop or steer. Owned-gating was never a
# policy choice, so the controls were unreachable by construction rather than merely unwired. Removed:
# claudeMissionControls (stop/steer), claudeFleetIdentityJoin (it correlates sidechain subagents by parentRunId, a
# problem missions do not have - a workflow agent is its own file in the mission's own directory - and its
# lifecycleOf only speaks for owned runs), each one's test, and the view's now-callerless appendRunRow /
# appendSubagentRow. Both modules had exactly one importer: their own test. The ownership probe stays: its id
# namespaces provably coincide, so it reports `foreign` because the runs genuinely are foreign, and it would
# resolve `owned` unchanged the day Clawdius launches a run.
#
# CORRECTION to the three blocks above: their numbers are each off by one commit. `diff-stat --check` measures
# BASE..HEAD (committed state), so running it before a commit reports the PREVIOUS commit's growth; each block's
# text therefore describes the right change but carries the prior one's delta, and the last commit's growth (+62)
# was never recorded at all - the baseline read 41615 against a HEAD of 41677, which CI would have failed on push.
# The prose in those blocks stands; only the arithmetic was misattributed. This number is measured against the
# WORKTREE (what HEAD becomes on commit), which is the measurement the recorded baseline must match.

# Disposition 2026-07-16 (+0 files, +78 insertions): close the journal's torn-record hole - the same gap the
# transcript reader had, in the same series. readJournal discarded every unparseable
# line under a comment claiming they were the expected half-written trailing record, but the catch covered EVERY
# line, so a tear mid-file dropped a `started`/`result` silently. Those records are what the agent counts are
# derived from, so a live mission read "agents: 4/5" for a 5/6 run while reporting completeness `complete` beside
# freshness `live` - a short count wearing a confident label. The reader now applies the transcript's own rule (skip
# only a non-terminated LAST line as the live tail; flag any other drop) and a tear degrades the mission, and its
# agent list, to `partial`. Measured against the real config root to settle which line is the tail: all 20 journals
# sampled end in '\n', so a complete journal never trips the tail skip - and the test fixture, which omitted the
# terminator, was the thing that was wrong; it now writes what the launcher writes. Also guards `agentId` with a
# path-safe charset before interpolating it into `agent-<id>.*`, matching the guard oobRef already applies, and
# drops a dead DisposableStore plus two doc links left dangling by the Run->Mission rename.
